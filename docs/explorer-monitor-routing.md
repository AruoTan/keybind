# 开始菜单与搜索跟随鼠标屏幕

原生部分位于独立项目 [windows-explorer](https://github.com/AruoTan/windows-explorer)，Windows 工作目录为 `E:\PROGRAMMES\explorer`。扩展不随 keybind 发布；本文记录两者的职责和目标 Windows 验收要求。

## 行为

按左或右 `Win` 打开原生开始菜单、按 `Win+S` 打开原生搜索时，面板出现在触发时鼠标所在的显示器。保留原生外观、动画、搜索和键盘导航，以及再次按键关闭面板的行为。其他 Win 组合键保持原功能。

每次打开锁定目标显示器，打开后移动鼠标不拖动面板。开始菜单切换到搜索时，搜索面板按首次显示时的鼠标位置选择屏幕。鼠标屏幕断开时退回系统选择。单屏沿用系统行为。

普通应用新窗口与 `Win+R` 由 keybind 处理，扩展不重复搬动这些窗口。两者使用 Windows 显示设备名称识别屏幕，无需新增通信接口。

## 实现边界

1. 首先核对目标 Windows 上的实际窗口与宿主。开始菜单通常为 `StartMenuExperienceHost.exe`，搜索通常为 `SearchHost.exe`；用进程、窗口类、所属关系共同识别目标，不依赖窗口标题。
2. 在面板决定布局前选择鼠标显示器；让宿主布局查询与最终窗口坐标使用同一目标。只对已识别面板及其布局调用链生效，不修改宿主所有显示屏查询的结果。
3. 搜索已有参考实现拦截 `MonitorFromWindow`、`MonitorFromRect`，再调整 CoreWindow 位置。仅从外部调用 `SetWindowPos` 可能被 XAML 布局覆盖。开始菜单需按其自身调用链验证，不能假定搜索的 Hook 可以直接复用。
4. 使用目标屏幕物理坐标、工作区和有效 DPI，适配负坐标、上下排列、不同缩放比例、任务栏布局与自动隐藏。保持面板的任务栏锚点，菜单不超出目标屏幕。
5. 不主动切换活动应用、改变主显示器、模拟鼠标点击、重启宿主或持续发送位置更改。不提升权限，不修改系统全局焦点策略。
6. Hook 支持卸载、宿主重启和显示布局变化；原始 API 保留可调用入口。处理重入时保持宿主读取到一致的目标，不能因屏蔽递归而重新暴露旧显示器导致布局回弹。
7. 不要求 keybind 拦截 Win 键。扩展只处理本机实际显示的系统面板；RDP 的其他 Win 组合键继续由客户端决定转发。

## 日志

每次打开记录触发来源、目标设备名、目标 DPI、宿主 PID、面板 HWND、原始与最终显示器，以及位置调用返回结果和失败后的系统错误码。布局结束后确认真实位置；记录失败并回退系统行为，不循环争抢位置。

不记录搜索词、输入内容或普通按键。没有遇到对应 API 调用时，不用旧的线程错误码推断失败原因。

## 验收

| 场景 | 通过条件 |
| --- | --- |
| 鼠标分别在主、副屏按 Win / Win+S | 面板第一次显示就在选定屏幕，不回弹；无需先点击屏幕 |
| 另一屏有活动应用、当前屏没有应用 | 仍按鼠标屏幕选择，不靠切换前台窗口实现 |
| 左右 Win、其他 Win 组合键、按键关闭面板 | 原生键盘行为保持；不误开开始菜单 |
| 开始菜单输入搜索、搜索后启动应用 | 面板沿用目标；新建主窗口交由窗口定位模块处理 |
| 搜索中移动鼠标、连续打开关闭 | 已打开面板不跟着鼠标移动，不积累延迟或 Hook |
| 副屏在主屏左侧或上方、不同 DPI | 坐标、尺寸、任务栏锚点和输入命中位置一致 |
| 插拔屏幕、任务栏自动隐藏、宿主重启 | 安全回退或重新适配，无失踪面板和宿主崩溃 |
| 全屏 Windows App / mstsc | 不把应交给远端的快捷键变成本机操作 |
| 与逐屏工作区同时使用 | 只影响系统面板所在屏幕，不切换或搬动其他屏幕应用 |

目标验收版本为 Windows 内部版本 `26300.9711`。参考实现声明的兼容范围不能替代本机验证。

参考：[搜索面板显示屏 Hook 源码](https://github.com/ereinaimer/windhawk-search-active-display/blob/main/search-active-display.wh.cpp)、[Windows 多显示器定位](https://learn.microsoft.com/en-us/windows/win32/gdi/positioning-objects-on-multiple-display-monitors)。
